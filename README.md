# MillieCat

TheCatAPI의 고양이 이미지를 목록·상세로 보여주는 iOS 앱입니다. 오프라인에서도 동작합니다.

## 빌드 방법

| 항목 | 버전 |
|---|---|
| Xcode | 26.4.1 |
| Swift 컴파일러 | 6.3.1 |
| 언어 모드 | 패키지 5종은 **Swift 6**, 앱 타깃은 **Swift 5 + 기본 격리 `MainActor`** |
| 최소 배포 타깃 | iOS 17.0 (앱 타깃) |
| 확인한 시뮬레이터 | iOS 26.4 |

> 앱 타깃만 Swift 5 모드입니다. 기본 격리가 `MainActor` 라 화면 코드는 별도 표시 없이
> 메인 스레드에 묶이고, 그 격리에서 빼야 하는 것(상태·Reducer)만 `nonisolated` 로 표시했습니다.
> 경계를 넘나드는 계층인 패키지 쪽은 Swift 6 모드로 두어 동시성 검사를 전부 받게 했습니다.

```bash
git clone <repo>
open MillieCat.xcodeproj   # ⌘R
```

의존성은 SPM이 자동으로 해결합니다. CocoaPods, Carthage, Tuist 같은 추가 설치 도구는 **필요하지 않습니다**.

> **첫 빌드는 수 분 걸립니다.** 외부 의존성인 Realm이 realm-core(C++)를 소스에서 컴파일하기 때문입니다.
> 두 번째 빌드부터는 캐시가 적용되어 빨라집니다.

## 의사결정 요약

| 항목 | 선택 | 이유 |
|---|---|---|
| 아키텍처 | MVI | 오프라인 × 로딩 × 캐시 조합이 많아 단일 State가 유리합니다. Reducer가 순수 함수라 테스트하기 쉽습니다 |
| 비동기 | Concurrency = 요청 한 번 / Combine = 끝없이 흘러오는 것 | 성격으로 나눴습니다. 연결이 끊기고 붙는 것은 `await` 로 표현되지 않습니다 |
| UI | 목록 = SwiftUI / 상세 = UIKit | 핀치 줌 3배는 `UIScrollView`로 네 줄이면 됩니다. 혼용 조건이 없었어도 같은 경계가 생겼을 것입니다 |
| 네트워크 | `URLSession` 직접 구현 | Alamofire를 쓰지 않았습니다. 외부 의존성을 줄여 클론 후 첫 빌드 성공률을 높였습니다 |
| 로컬 저장 | Realm(메타데이터) + 파일시스템(이미지) | 과제가 "local DB에는 메타데이터를"로 한정했기 때문입니다 |
| 모듈 | 로컬 SPM 5패키지 | 의존성 0인 모듈에서는 계층 위반이 컴파일 에러가 됩니다. 나머지는 접근 제어로 막습니다 |

자세한 근거와 트레이드오프는 [DESIGN.md](DESIGN.md)에 있습니다.

## AI 도구 사용

**Claude Code (Opus)** 를 사용했습니다.

경계는 **"판단이냐 타이핑이냐"** 로 그었습니다.

| 직접 | AI에 위임 |
|---|---|
| 아키텍처, 계층 경계, 모듈 이름 규칙 | 정해진 인터페이스에 맞춘 구현 |
| 인터페이스·프로토콜 선언 | UI 조립, 형태가 정해진 반복 코드 |
| 상태 전이 규칙, 테스트가 확인할 항목 | 그 규칙의 코드화, 테스트 코드 |
| 라이브러리를 쓸지 말지 | 이름 일괄 변경 같은 기계적 작업 |

검증·수정 절차와 개별 기록은 [AI_LOG.md](AI_LOG.md)에 커밋 단위로 남겼습니다.

## 확인한 범위

| 항목 | 수 |
|---|---|
| 패키지 단위 테스트 | 47 |
| 앱 타깃 단위 테스트 | 56 |
| 화면 자동화 테스트 (XCUITest) | 3 |

```bash
xcodebuild test -project MillieCat.xcodeproj -scheme MillieCat \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -parallel-testing-enabled NO
```

> 화면 자동화 테스트는 앱을 그대로 띄워 실제 서버에서 목록을 받아옵니다.
> 연결이 없거나 호출 제한에 걸리면 기능과 무관하게 실패할 수 있습니다.

## 의도적으로 하지 않은 것

적지 않으면 버그로 보이고, 적으면 선택으로 읽히는 것들입니다.

- **iPad 전용 화면** — 일반 폰을 전제로 만들었습니다. 가로·세로 규격도 폰 기준입니다
- **가로에서 다섯 칸을 한눈에 보여주는 것** — 한 줄에 다섯 칸이 들어가지만 화면 폭보다 넓어, 처음에는 약 3칸만 보이고 나머지는 오른쪽으로 밀어야 나옵니다. 세로 이동과 가로 이동을 분리한 대가입니다 ([DESIGN.md](DESIGN.md) 참고)
- **화면 자동화 테스트의 응답 대역화** — 앱에 테스트 전용 통로를 내야 해서 두지 않았습니다
- **이미지 캐시 용량 제한** — 과제 범위에서 무한히 커질 상황이 아니라 두지 않았습니다
